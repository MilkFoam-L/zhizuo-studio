# 个人账号与工作空间

`apps/server/src/accounts.ts` 提供个人账号认证和会话服务。每个账号拥有一个个人工作空间；当前没有共享团队、邀请成员、共同编辑或跨账号访问作品的授权模型。`admin` 是账号管理角色，不能据此获取其他账号的作品或模型密钥。

## 数据与初始化

`AccountService.initialize(bootstrap?)` 创建以下独立关系表，不复用旧版共享密码的 `documents/sessions`：

| 表                | 保存内容                                           | 约束                                 |
| ----------------- | -------------------------------------------------- | ------------------------------------ |
| `auth_users`      | 邮箱、显示名称、密码哈希、角色、禁用状态、创建时间 | 邮箱唯一；角色为 `admin` 或 `member` |
| `auth_workspaces` | 空间 ID、所有者、名称                              | 一个账号对应一个个人空间             |
| `auth_sessions`   | 会话令牌哈希、账号 ID、过期时间                    | 删除账号时级联清除；禁用时撤销会话   |

只有在没有任何账号时，传入的 bootstrap 配置才会创建首个管理员。重启时不会根据配置修改现有密码、邮箱或显示名称。配置不具备密码重置功能。本模块不登记迁移版本号，由应用层统一管理迁移。

创建账号和个人空间使用一条数据修改 CTE，任一插入失败则整条语句回滚。邮箱会去除首尾空白并统一小写；不进行 Gmail 点号或加号别名合并。显示名称允许 1–80 个字符，禁止控制字符。

## 密码与会话

- 创建密码长度为 12–256，不会自动去除密码空白，也不会写入数据库、日志或公开返回值。
- 密码使用 Node.js 异步 scrypt，参数为 `N=32768, r=8, p=1`，随机 16 字节盐，64 字节派生值；哈希包含固定参数和盐。
- 比较派生值使用 `timingSafeEqual`。不存在的邮箱也会执行相同参数的 scrypt；邮箱不存在、密码错误、账号禁用和无效登录输入统一返回「邮箱或密码不正确」。这降低账户枚举风险，但不宣称网络请求耗时完全恒定。
- 登录成功生成 32 字节随机令牌，仅返回给调用层一次；数据库保存其 SHA-256。会话有效期 7 天，不自动续期。
- 会话查询同时检查过期时间和账号禁用状态。退出登录撤销当前令牌；禁用账号撤销其全部令牌；重新启用不会恢复旧会话。
- 旧共享密码模式的会话不能用于个人账号登录。

## 服务接口

| 接口                                                               | 返回内容                                               |
| ------------------------------------------------------------------ | ------------------------------------------------------ |
| `initialize({ email, password, displayName? }?)`                   | 初始化表，可选首次管理员                               |
| `createAccount({ email, password, displayName }, role = 'member')` | `PublicAccount`                                        |
| `login(email, password)`                                           | `{ token, user, expiresAt }`，`expiresAt` 为 Unix 毫秒 |
| `session(token)`                                                   | 当前 `PublicAccount` 或 `undefined`                    |
| `logout(token)`                                                    | 撤销当前会话，重复调用安全                             |
| `listAccounts()`                                                   | 管理页面使用的公开账号列表                             |
| `setDisabled(id, disabled)`                                        | 更新后的 `PublicAccount`                               |

`PublicAccount` 只包含 `id`、`email`、`displayName`、`role`、`disabled`、`workspace: { id, name }`、`createdAt`；不包含密码哈希或任何会话令牌。

业务错误通过 `AccountError` 的 `statusCode` 和 `code` 表达：无效凭据 `INVALID_CREDENTIALS/401`、重复邮箱 `ACCOUNT_EXISTS/409`、账号不存在 `ACCOUNT_NOT_FOUND/404`、最后一个活动管理员 `LAST_ADMIN/409`。其他创建输入错误使用 Zod 验证错误。

## 应用层集成责任

这些服务方法没有 HTTP 上下文，因此调用层负责以下行为：

1. 对创建、列举、禁用账号接口检查当前用户为管理员；公开注册默认关闭。
2. 登录接口按来源限制尝试次数；在反向代理之后正确处理受信任代理，避免将任意传入的转发头作为客户端身份。
3. 将令牌放入 `HttpOnly`、`SameSite` Cookie，HTTPS 托管时使用 `Secure`；继续执行既有来源校验和私有接口 `Cache-Control: no-store`。
4. 从服务端会话读取工作空间 ID。项目、素材、版本、任务、服务商配置及导出均使用该空间；不能信任浏览器提交的所有者或空间 ID。
5. 限制管理页面中邮箱列表的访问。管理员创建账号时的明文初始密码只用于本次创建，不应通过日志或账号列表再次展示。

最后一个活动管理员的禁用检查和会话写入在同一 `Database` 实例上串行化，并用 SQL 条件再次约束。此实现匹配当前单进程应用部署；多个进程或多个数据库连接包装实例同时管理账号时，需要先加入数据库事务级互斥，再扩展部署。不能把单进程并发测试当作多实例保证。

当前服务没有密码重置、邮箱校验、自助注册、修改密码、团队成员、细粒度权限或外部身份提供商。需要这些能力时应增加对应流程、会话撤销策略和测试；不要用修改 bootstrap 配置替代账号恢复。

## 验证

运行 `npx tsx --test apps/server/tests/accounts.test.ts`，使用真实临时 PGlite 数据库，无外部身份服务、真实账号或网络调用。

测试覆盖：首次管理员与重启保持、邮箱唯一与并发创建、个人空间插入失败的事务回滚、随机盐、公开数据不含秘密、统一登录错误、令牌哈希、旧会话命名空间隔离、7 天过期、退出与禁用撤销、重新启用不恢复会话、并发禁用保留管理员、输入边界及数据库重开后的持久性。

模块测试不证明 HTTP 权限、跨空间资源隔离、Cookie 配置、登录限流或真实 PostgreSQL 部署已通过。这些需要应用集成测试分别验收。

## 账号生命周期与保留策略

- 自助改密（`POST /api/account/password`）校验当前密码并吊销该账号全部会话；管理员重置（`POST /api/admin/accounts/:id/reset-password`）同样吊销全部会话。
- 账号数据导出（`GET /api/account/export` 与管理员版）：每个项目一个标准项目备份 ZIP，外加 manifest.json；上限 500 MB。
- 账号删除（自助 `DELETE /api/account` 或管理员 `DELETE /api/admin/accounts/:id`，均需密码确认、最后一位管理员受保护）：先终止排队/运行中的任务，再删除项目、素材对象、版本、任务、渠道、品牌、分享、邀请、额度策略/窗口/预占与工作空间及全部会话。**额度审计事件（quota_events）按合规要求保留**，不属于用户数据删除范围。
- 删除不可恢复；界面在删除前引导先导出数据。测试见 `apps/server/tests/account-lifecycle.test.ts`。
