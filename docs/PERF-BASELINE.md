# 画布性能基线（200 混合节点 / 50 图片）

更新：2026-10-07。设备：本机开发环境（Apple Silicon，headless Chromium 1280×900，dev 模式 Vite 未压缩构建）。这是首次记录的基线，不是优化结论；后续优化以此为对照。

## 数据集

- 项目 `8bebdb77-efca-417d-b158-5ce42d04cbe5`（本地 PGlite，dev 数据目录）
- 50 张真实 PNG 素材（300×400，各 ~3-6 KB，经 Sharp 归一化）
- 画布 200 个业务节点：brief 1 + asset 50 + copy 30 + prompt 30 + annotation 30 + group 10 + poster 49（含完整文本图层）
- React Flow 渲染节点（含端口/句柄）250 个

## 结论与边界

- 200 节点规模下加载、内存与缩放交互在本机 dev 环境均可用；未做优化改动（符合"仅出现明确瓶颈才优化"的约定）。
- 缺口：真实用户设备（含低端安卓/平板触控）、生产构建（压缩+分包）、拖拽与多选操作的帧率、长时间会话的内存增长（泄漏排查需 heap snapshot 对比）。移动端触控与窄屏归入 B1 遗留项。
- 复测：`node --import tsx work/perf-seed.mts` 重建数据集（需先启动 dev），浏览器打开项目后用相同指标复测。
