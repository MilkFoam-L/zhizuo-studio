# 独立任务执行与数据库租约

适用版本：实现 `workerId`、`leaseToken`、`leaseExpiresAt` 的任务执行器。API 与 worker 通过同一 PostgreSQL 数据库协调，节点内存中的任务表不作为所有权依据。

## 执行与部署边界

本地 PGlite 继续使用单进程的内嵌 worker。它的单个数据目录不能由多个进程同时打开；独立 API / worker 和多 worker 使用 PostgreSQL，以及所有节点可访问的同一私有素材存储与加密密钥。具体启动命令、角色环境变量见 README 与 `.env.example`。

每个 worker 默认最多并行 2 个任务，默认租约 60 秒、心跳 10 秒。数据库时间决定租约是否有效，避免不同主机时钟漂移导致双重领取。测试可通过执行器选项调整这两个间隔，它们不属于创建任务的用户输入。心跳必须短于租约时长的一半。

独立 worker 入口传入 `keepAlive=true`，保持调度定时器引用；API 内嵌执行器默认不以定时器阻止进程退出。

`JobRunner` 的 `tick()` 适用于单次调度；`start()` 启动周期调度；`stop()` 停止领取、取消本地等待、等待已经开始的数据库处理和任务结束，并清理心跳定时器。API 进程可只创建一个未调用 `start()` 的执行器，调用 `cancel()` 仍会通过数据库取消独立 worker 的任务。

## 领取、提交与恢复

1. 事务锁住指定任务记录，重新检查队列状态、恢复期限、账号与工作空间权限。
2. 领取成功写入随机 `leaseToken`、本进程 `workerId` 和数据库计算的过期时间。其他 worker 的事务看到最新状态后放弃领取。
3. 真正调用服务商前，再次检查租约、任务状态、账号权限和取消信号；先提交 `submissionStarted=true` 与 `submissionStartedAt`。这项记录表示“可能已发出收费请求”，不证明服务商已收到。
4. 网络请求在数据库事务外执行。心跳只持有短事务，观察数据库里的取消、禁用和失租，再续租或中止本地等待。
5. 收到异步任务编号后持久保存。一个已经取消或刚失租但仍是相同 token 的任务可以补充收到的编号，供用户核对；此写入不改变任务状态。新 token 已接手时拒绝旧 callback。
6. 启动和周期调度只处理已过期的 `running` 任务。显式记录 `submissionStarted=false`、没有提交时间和上游编号的任务可安全回到队列，并移除旧 token，使旧进程无法随后提交；其余任务转为 `reconciling`。活跃租约保持原状。没有 checkpoint 字段的旧版运行任务保留未知语义，进入核对。
7. 已保存异步任务编号、仍在 15 分钟恢复窗口且未超过 3 次恢复尝试的任务可继续 GET 原任务；保留 5 / 15 / 45 秒退避和取消能力。结果未知且没有编号的任务不会自动重新 POST。即使误回到 `queued`，已有提交 checkpoint 也阻止重复提交。

没有远端幂等协议时，无法承诺供应商计费 exactly-once。checkpoint 后进程崩溃、连接断开或响应丢失，都可能无法判断收费请求是否被接收。界面会保留核对状态和任务编号，操作者应先核对原任务与账单。

## 发布与取消

生成图片先进入素材存储，此阶段不占用发布事务，API 取消与心跳能继续执行。随后在一个短数据库事务中完成租约检查、版本写入、画布节点追加和任务成功状态；最后更新还必须匹配 token 和有效租约。任一语句失败或发布期间租约过期，整个版本与画布修改回滚。

不同进程的 `cancel()` 与发布锁同一条任务记录：取消先提交则执行器无法发布；发布先提交则取消返回已经成功的任务。心跳检测远端取消并 abort 本地供应商等待。停止本地等待不保证服务商取消或退款。

清理只针对当前调用自己创建且没有被其他版本或画布引用的素材。旧 worker 不按 taskId 删除版本，避免删掉替代 worker 已提交的结果。`removeIfUnreferenced` 对素材记录取得独占锁后复查版本、海报、输入来源快照和画布引用；`Repository.version/update` 写入引用前按素材 ID 排序取得共享锁并校验项目归属。清理先完成时，后来的引用写入会拒绝不存在的素材；引用先完成时，清理会保留素材。服务商已完成但本地结果保存或清理失败时，记录核对状态，避免自动多次发布。

任务公开数据不包含服务商密钥、配置快照、恢复调度字段、worker 身份、租约 token、租约期限和提交 checkpoint。它们只在服务器保存。

## 多进程媒体上传与清理

每次上传先持久化 `uploadOwner`、随机 `uploadToken` 和数据库计算的 `leaseExpiresAt`；默认上传租约 180 秒、心跳 20 秒。每次对象 PUT 前和素材元数据事务提交前都检查 token、上传阶段和有效租约。对象存储调用在数据库事务外执行，数据库连接和行锁不会被整个远端请求占用。元数据写入结束时再次检查期限；期间失租会回滚元数据，阻止旧上传成功返回。

其他 worker 的定期 `reconcilePending()` 只能清理已经过期且没有可用素材记录的上传。已有素材元数据时仅移除 pending 记录，保留图片和缩略图。旧格式的 pending 没有租约时，根据 `createdAt` 保留 180 秒宽限期；不会把刚写入的记录视为失效。清理前先在短事务内标记 `cleaning` 并领取清理 token，使旧上传无法发布元数据；实际对象删除在事务外执行。

上传租约过期时，原进程发出的 PUT 可能仍在对象存储中执行。清理完成后会保留一个禁止发布的 pending 标记并继续扫描，防止晚到 PUT 重新留下无人追踪的对象。原上传调用返回后会确认 `uploadStopped`，再次清理并移除标记。如果原进程永久退出而无法确认停止，该标记会保留；扫描可以反复安全删除其对象。此选择优先保证残留对象可追踪，运维应观察此类记录数量和对象存储删除请求量，不应仅按一次清理成功就强行移除标记。

删除无引用素材时，先在数据库事务中移除素材可见记录并建立清理意图，再删除实际对象。即使对象删除失败，新引用也会因素材记录不存在而被拒绝，后续扫描可以完成对象清理。用于失败导入补偿的 `Media.remove()` 保留显式强制删除行为，调用方必须只传本次导入拥有的资源。

`Media.close()` 拒绝新上传，等待正在进行的上传、心跳和清理结束。API 与 worker 应先停止清理定时器、排空正在运行的请求和任务，再 `await media.close()`，之后关闭对象存储连接和数据库。测试可以通过构造函数第 4 个参数调整租约、心跳和 legacy 宽限期；这些选项不暴露给上传请求。

## 结算接口

`JobExecution.onTaskSettled(task)` 在非运行状态已经提交后执行，包括 `succeeded`、`failed`、`cancelled`、`reconciling`。回调必须幂等，并读取数据库中的最新任务状态；跨进程取消、执行器收尾和失租扫描可能重复通知，也可能在崩溃后缺少一次通知。额度模块应使用持久预留记录与扫描补偿，不能依赖回调作为唯一结算来源。

新任务创建时写 `submissionStarted=false`。旧记录没有该字段时保留未知语义，不能把历史缺字段自动解释为“从未发送”。`usage` 记录随最新状态写入，供应商未报告的价格保持 `cost=null`，不推测金额。

## 发布前验证与迁移

升级旧执行器时先停止旧 worker 并备份数据库、素材与密钥，再启动支持租约的新版本。旧执行器不认识 fencing，混跑无法保证互斥。旧版运行任务首次启动会进入核对；不会尝试重复提交已可能收费的请求。回退版本也需先停止全部新 worker，防止无租约旧版本重置活任务。

已有测试覆盖：两个执行器只有一次请求；新进程启动不重置活租约；续租和跨执行器取消；终止后无继续心跳；过期无编号不会 POST；异步 ID 持久重开后仅 GET；过期 token 无法发布或改写异步编号；旧执行器清理保留新版本；事务发布与取消串行；停用账号后的发布阻断；恢复次数与截止时间；丢失提交响应与事务回滚。

PGlite 测试验证逻辑与持久重开；实际 PostgreSQL 的多连接 / 进程测试结果以阶段验证报告为准。测试注入供应商响应，不代表真实云服务、网络、凭据与计费已经验收。
