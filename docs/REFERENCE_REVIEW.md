## 2. 多方模型接入：应落实到产品合同

infinite-canvas 的固定提交将 `ModelChannel` 定义为独立渠道，含渠道 ID、名称、Base URL、密钥、API 格式、模型列表；模型具有文字、图片、视频、音频能力标识。模型选择绑定渠道，避免不同服务的同名模型混淆。

织作应有以下真实能力：

1. 用户可建立多个渠道，分别录入名称、Base URL、API Key、接口协议和模型名称；官方服务和用户有权使用的中转服务都走同一个配置入口。
2. 文案模型、图片模型分别选择；保存稳定的渠道 ID 和模型名称，生成记录保存当时的配置摘要，但不包含密钥。
3. “兼容 OpenAI”是接口协议选项，不代表任意服务、模型都支持全部能力。图片生成、参考图编辑、结构化文本输出分别声明支持情况。
4. 连接检测和实际生成分开显示结果。模型目录接口不可用时，允许手动填写模型；不能仅凭 `/models` 成功就显示“生图验证通过”。
5. 请求由织作后端转发，服务端使用密钥；前端读回仅有脱敏状态。持久化密钥需有明确保护方式，项目导入导出与日志均排除密钥。
6. URL 使用结构化解析，明确保留用户填写的路径前缀；避免重复添加 `/v1` 或错误截短域名。凭据不能随重定向转发到其他主机。
7. 云端部署需约束后端出站目标：阻断元数据地址与非授权内网目标；自托管连接本地服务时，由部署配置明确允许。不能因提供中转接入就暴露通用公共代理。
8. 将 401 / 403、限流、超时、响应格式错误、部分图片失败分别反馈；有取消、单项重试和任务恢复。超时后的付费请求不能无条件重复提交。
9. 图片响应的 URL / Base64 / Data URL 按协议适配并设置类型、大小、下载超时边界；远程临时 URL 应转存为项目资产，防止过期后作品丢图。
10. 私有异步接口采用显式适配器与配置合同。第一阶段应列出已支持协议，后续逐个扩展；不通过执行用户上传脚本实现全能接入。

上述是从上游能力和真实部署需要推导的织作实现要求，不能视为已实现清单，也不保证任意中转站的兼容性。外部仓库中的服务推广、价格和可用性说明没有在本轮核验，不作为默认供应商推荐。

## 3. 小红书内容生产：落地方式

流程可以吸收 RedInk 的分步编辑与单页重试，以及 Visual Director 的母版一致性：

- **商品事实**：商品名、真实卖点、规格、价格、促销条件、适用场景、禁写项与用户上传素材。缺失事实留空，不让模型补造资质、销量、功效或使用经历。
- **内容简报**：受众、目标、语气、平台、页数、品牌色；以简单表单承接，避免把外部 Agent Skill 的十轮问答直接塞进普通用户流程。
- **图文大纲**：每页有用途、标题、正文、视觉方向；先生成可编辑结构，用户可单页重排、修改或重新生成。
- **统一母版**：固定比例、文字层级、品牌色、图片区域和安全边距；同一组图保存母版版本。
- **可编辑海报**：AI 用于背景、场景和视觉素材；中文标题、价格、卖点以真实文本图层排版。用户修改一个数字不应触发整张图片重新生成。
- **内容版本**：每次文案或海报变体建立新版本并关联输入事实、模型与父版本；恢复历史不能覆盖仍在处理的任务输出。
- **交付包**：逐页 PNG、标题/正文/话题文本、项目备份；用户在平台官方入口审核后发布。

预设 3:4 可以作为本产品模板设计，但不能把 GitHub 项目默认比例、字符数或社区经验当成小红书官方最新规则。官方发布约束应单独核查，并版本化管理。当前参考研究不包括自动登录、自动发布、绕过访问限制、热帖抓取或第三方 Cookie 使用。

## 4. 实现验证建议

| 场景 | 通过证据 |
| --- | --- |
| 两个中转渠道包含同名模型 | 请求记录显示各自渠道 ID / URL 正确，密钥互不串用 |
| 用户填写带 `/v1` 或其他路径前缀的 Base URL | 合同测试验证最终 URL，无重复版本路径 |
| 图片服务支持生成但不支持参考图编辑 | UI 如实提示能力，不能回退成没有使用商品图的生成并声称已编辑 |
| 返回临时 URL、Base64、非图片或超大文件 | 支持格式落到资产；异常返回明确错误；不把任意文件当图片执行 |
| 生成中刷新、取消或同页重试 | 任务状态恢复；重复请求不创建重复结果；已有成功页保留 |
| 中文标题过长、价格修改、多尺寸导出 | 文本可编辑；溢出有反馈；导出内容与预览一致 |
| 商品事实缺价格、销量和功效信息 | 产物不捏造具体值，保留待填写状态 |
| 导出项目与诊断信息 | 不包含渠道 API Key、会话凭据或供应商授权头 |
