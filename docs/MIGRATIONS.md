# 数据、执行器与认证模式迁移

## 当前版本

- 文档格式仍为 `schemaVersion=1`。项目新增可选 `workspaceId`；旧记录没有该字段时，按 `local` 工作空间处理。
- 基线数据库迁移记录为1；启用账号模式后添加 `auth_users`、`auth_workspaces`、`auth_sessions`，并登记迁移2。这是增加表，不删除原项目或更改已有渠道密钥。
- worker / 额度阶段基于 `2924761`，增建 `quota_policies`、`quota_windows`、`quota_reservations`、`quota_events` 与 `runtime_config`，登记迁移3。账号表仍只在 accounts 模式初始化；迁移编号不是通用迁移执行器或可自动回退的承诺。
- `tasks` 增加执行所有者、租约 token / 到期时间、`submissionStarted` / `submissionStartedAt` 等服务端字段；不将这些内部字段暴露给前端。旧任务不补造“从未提交”的证据。
- 未完成上传使用 `documents(scope='pending_assets')`，新增上传所有者、token、租约到期和清理阶段字段。旧格式记录按创建时间保留180秒宽限后才可回收；可能仍有晚到PUT时保留可继续清理的标记。
- 额度、运行配置、任务和 pending 均不属于项目ZIP的可恢复服务状态，整实例备份必须保留；项目文档仍为 `schemaVersion=1`。

## 升级至带租约的 worker 与任务额度

1. 停止接收新任务，停止全部旧 API / worker。旧版执行器不检查租约 token，不能与新版本混跑；等待已知网络请求结束，并记录仍需向供应商核对的原任务。
2. 备份一致性的数据库、素材和原加密密钥。数据库备份包括任务、账号、pending，以及已经存在的全部额度 / 审计表；恢复时不拆开任务和预占记录。
3. 本地 PGlite 继续使用 `WORKER_MODE=inline`；其数据目录不能被多个进程打开。独立执行器必须使用 PostgreSQL，并给 API / worker 配置同一 `DATABASE_URL`、固定 `ENCRYPTION_KEY`、认证模式和共享素材位置。
4. 先启动 API 完成初始化、迁移记录和首次管理员创建。`runtime_config` 保存认证模式、密钥指纹及存储位置；worker 启动时必须匹配，执行中发现配置变化也会停止对应工作。更换已有实例的加密密钥会被拒绝，当前没有自动密钥轮换。
5. 使用 `WORKER_MODE=external` 启动 API，再执行 `npm run start:worker` 启动已构建 worker。检查 health、任务领取、取消、恢复及额度页面；独立 worker 不负责首次管理员创建。
6. 核对遗留任务和上传记录。仅“明确未提交、没有提交时间、没有上游编号”的过期运行任务可回队；旧字段缺失或可能已提交的任务进入核对，保留异步ID时才在既有限额内继续GET原任务，不重新提交可能收费的请求。

`MAX_DAILY_TASKS` 只给新空间策略提供默认值，不覆盖已经保存的限额。历史任务没有预占记录时不会补扣或补记供应商费用；新任务的预占与入库在同一事务中完成。跨日结束或人工核对都修改原预占日期窗口。人工释放恢复的是平台任务次数，没有申请供应商退款或修改其账单。详见 `WORKERS.md`、`QUOTAS.md`。

此流程已在隔离环境验证增表、真实 PostgreSQL 多 worker、强杀后核对与编译入口启动；未做生产升级、云端备份恢复或灾备演练。当前验证范围是一个 API 配多个 worker，多 API 的账号管理、限流和完整监控仍需专门验收。

## 从本地/共享密码模式启用账号

1. 在原模式中，逐项目导出包含素材的 ZIP；停止服务后备份 PGlite 整个目录或使用 PostgreSQL 的一致性备份，并备份加密密钥。不要复制正在写入的 PGlite 文件后假定一致。
2. 保留原实例和数据备份。配置 `AUTH_MODE=accounts` 与首次管理员资料，再启动目标实例。
3. 使用对应账号登录并导入其自己的项目备份。导入总是创建新ID，归属于当前账号；不会信任备份中携带的旧 workspaceId。
4. 原 `local` 资料仍留在数据库中，账号模式下不可访问，也不会自动赠给管理员。若需回看原资料，可在隔离的原模式备份实例中读取。
5. 模型渠道密钥不包含在项目ZIP中，需要每个账号自行重新配置。

这是有意识的导入流程，不是透明迁移。直接切模式不会删除作品，但看不到旧资料是预期的权限隔离结果。没有配套归属迁移脚本时，不应批量修改 workspaceId。

## 队列与模式切换

worker 在领取、供应商提交 checkpoint、续租和结果发布时检查所属空间、账号与运行配置。停用账号、账号模式下的旧 local 队列、local/shared 模式下的个人账号队列，都不会继续发起新的模型请求或发布结果。这些任务会停止本地执行并保留说明；已发出的远端请求可能继续，不要据此推断上游任务退款或取消。

切换认证模式或存储配置前停止全部 worker，先由 API 写入当前运行配置，再以相同配置启动 worker。`runtime_config` 一致性检查不能代替迁移旧项目归属或搬迁素材文件。

## 切换媒体后端

本地文件与S3不是自动镜像。导出旧后端项目ZIP，在独立测试数据目录使用新后端导入并检查原图、缩略图、导出和备份，再切换服务。恢复后的素材ID不同，引用会重映射。

pending记录保存不含凭据的存储位置标识；仅对当前后端对应的记录清理，不处理其他路径/桶/前缀。更改对象存储访问凭据但不改变存储位置可以继续恢复；这不等于更换应用加密密钥。未知位置的pending应由管理员保留并按原后端配置处理。清理标记可能等待原上传确认停止，不能因一次对象删除成功就直接删除可能有晚到PUT的标记。

## 回滚

本轮可对照的代码基线为账号 / 存储阶段提交 `2924761`。回退到无租约执行器前，必须停止接收新任务并停止全部新 API / worker，再恢复与该版本配套的升级前数据库、素材及原密钥；旧执行器可能重置运行任务，直接连到新执行器仍在使用的数据无法保证互斥。恢复任务数据时同步恢复额度策略、窗口、预占与审计，不删除额度表或重置历史状态来“修正”计数。恢复旧备份不能撤销供应商已接收的请求，遗留任务仍需对照原任务编号 / 账单核对。

更早的账号阶段基于 `cf84867`。若进一步回退到账号隔离之前的代码，必须同时使用启用账号模式前的数据备份；不能把旧版全空间读取逻辑指向已有多账号数据的生产库。优先保留现有版本，用新提交修复；必要时在隔离环境验证代码与数据的一致性回退。

没有执行任何生产迁移、实际用户账户变更或远端数据删除。本阶段验证使用独立临时目录与本机隔离 PostgreSQL；测试供应商为 fixture，真实供应商费用与 S3 桶未验收。
