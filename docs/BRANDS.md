# 品牌资料库

品牌资料属于当前工作空间，可保存品牌名称、主色、辅助色、表达语气、禁用词、字体和 Logo。资料库支持新建、编辑、归档与恢复；归档品牌在默认列表中隐藏，勾选「显示已归档品牌」后可以恢复。

## 应用到项目

在项目简报中选择品牌并确认应用。应用会一次更新简报中的品牌名称、主色、语气、字体、禁用词和 Logo，同时记录品牌编号及应用时的修订版本，并把商品事实确认状态设为未确认。应用前应先保存简报中需要保留的修改。

Logo 会复制成目标项目自己的素材。此后修改品牌、替换 Logo 或归档品牌，都不会自动更新已经应用的项目，也不会修改已保存的内容版本或导出作品。再次应用品牌需要用户明确操作。辅助色保存在资料库中，当前简报和模板使用主色。

可选字体为思源黑体（`sans`）和思源宋体（`serif`），由工作台提供字体资源。禁用词传入文案生成约束；人工编辑和供应商生成结果仍应由用户检查。

## 约束与授权

- 名称 1–80 字；颜色必须为 `#RRGGBB`；语气最多 1000 字。
- 禁用词最多 100 个，每项 1–80 字，界面每行填写一个。
- Logo 最多 4 MiB，只接受静态 JPG、PNG、WebP、AVIF。服务端解码后旋转、缩放至最长边不超过 1024 像素，并通过现有 Media 服务归一化保存为 PNG。
- BrandInput 不接受 `logoAssetId`，不能绑定其他项目或空间的素材。品牌源 Logo 使用内部 `brand:<品牌编号>` 素材命名空间，不创建用户项目。
- 源 Logo 只通过经过工作空间授权的品牌 Logo 路由读取。应用到项目后的独立副本遵循普通项目素材授权。

## 并发与失败处理

品牌资料有独立 `revision`。编辑提交携带原修订号，冲突返回 409，界面保留本地表单。归档和恢复使用行锁并增加修订号。

上传先读取品牌修订号，图像处理和远端写入在数据库事务之外完成，随后在短事务中锁定新素材、核对品牌修订号并发布 Logo。上传期间发生品牌编辑时保留当前品牌，只尝试清理本次未引用的上传。

应用品牌时先在共享锁保护下读取源 Logo，再在事务外复制到项目。最终提交再次检查品牌状态与修订号，并使用项目修订号更新简报。任何竞争失败只清理本次新建且未被引用的副本。读取源 Logo 时保留共享素材锁，避免替换清理抢先删除正在读取的对象。

已经引用的素材由 Media 的引用检查保留；远端删除失败会留下既有媒体清理意图，由后台清理恢复。上传中断产生的残留沿用 Media 的上传租约与恢复机制。

## API

| 方法与路径                           | 用途                                                               |
| ------------------------------------ | ------------------------------------------------------------------ |
| `GET /api/brands`                    | 当前空间未归档品牌；`?archived=true` 包含归档项                    |
| `POST /api/brands`                   | 新建品牌                                                           |
| `GET /api/brands/:id`                | 获取当前空间品牌                                                   |
| `PUT /api/brands/:id`                | `revision` 加品牌字段更新                                          |
| `PATCH /api/brands/:id/archive`      | `{ archived: boolean }` 归档或恢复                                 |
| `POST /api/brands/:id/logo`          | multipart 上传专用 Logo                                            |
| `GET /api/brands/:id/logo`           | 经授权读取品牌 Logo PNG                                            |
| `POST /api/projects/:id/apply-brand` | `{ brandId, revision }`；revision 为项目版本，返回更新后的 Project |

## 验证与回滚

`npx tsx --test apps/server/tests/brands.test.ts` 使用真实 PGlite 和 Sharp，覆盖工作空间隔离、严格输入校验、版本冲突、图片归一化、项目 Logo 独立、归档后历史保留，以及复制或上传时的并发变更。`npm run typecheck` 与 `npm run build` 验证静态集成。浏览器交互验收状态以本轮最终验证记录为准。

本模块新增 `brand_kits` 文档作用域，未迁移或批量改写已有项目。回滚应用代码可保留品牌文档与素材；恢复旧版本前需备份数据库、素材和加密密钥，避免旧版本缺少 Logo 引用保护时执行素材清理。不要为回滚直接删除品牌素材，因为项目和历史内容可能持有独立副本。
